# Historical grouped nested-validation outputs

The validation metrics, sensor-selection summaries, and ADC quality-control outputs in this directory are generated by [`../../code/analysis/nested_grouped_classification.py`](../../code/analysis/nested_grouped_classification.py). They replaced the earlier MATLAB holdout results at a previous development stage and remain unchanged as historical records. They are not the current classifier's results. Use the [within-recording random-sample package](../../code/analysis/within_recording_random_split/README.md) for the current 96.16% mean-accuracy analysis, its matched comparisons and current Figures 9 and 10. The separate `participant_posture_medians.csv` table is generated by [`../../code/analysis/make_figure7_participant_responses.py`](../../code/analysis/make_figure7_participant_responses.py) and supports descriptive Figure 7 rather than classification.

## Validation design

- Participant-specific five-fold outer validation, grouped by repetition number.
- Samples sharing a stored repetition group are kept in one fold. Stored labels do not by themselves guarantee that a complete physical cycle and its associated return are grouped together.
- Non-overlapping one-second windows are built separately inside each phase and repetition.
- Sensor selection is performed only on the outer-training data using four inner repetition folds.
- Imputation and standardization are fitted inside each training fold.
- The selected single sensor, pair, and triplet are compared with all ten sensors on the same outer partitions.
- Held-posture windows formed this historical workflow's primary analysis. Transition windows were a secondary test of models trained only on held postures.

## Historical pooled out-of-fold results

| Configuration | Accuracy | Balanced accuracy | Macro-F1 | Held-window support |
|---|---:|---:|---:|---:|
| Nested-selected single sensor | 43.60% | 35.94% | 35.55% | 2032 |
| Nested-selected pair | 50.30% | 45.18% | 45.04% | 2032 |
| Nested-selected triplet | 55.22% | 49.35% | 50.57% | 2032 |
| All ten sensors | 63.78% | 53.16% | 58.22% | 2032 |

No triplet was consistently selected. The most frequent selected triplet occurred in only 2 of 15 participant-by-outer-fold analyses, so the results do not support a uniquely optimal three-sensor configuration.

For the ten-sensor model, the held-posture error rate was 36.22% and the transition-period error rate was 76.88%. The only channel with more than 1% near-saturation samples was S9 for participant S2 (1.86%). Excluding S9 produced similar pooled results (balanced accuracy 52.77%), indicating that the main comparison did not depend on that channel.

See `analysis_settings.json` for exact settings and software versions, `outer_fold_results.csv` for fold-level metrics, `participant_posture_metrics.csv` for class support and recall, and `adc_quality_summary.csv` for channel-level signal-quality checks.

## Reproduction

From the repository root, after installing `requirements.txt`, run:

```bash
python code/analysis/nested_grouped_classification.py \
  --inner-trees 20 \
  --outer-trees 100 \
  --out-dir results/nested_grouped_reproduced
```

This writes a fresh set of historical-workflow metrics, fold-level selections, `outer_fold_predictions.csv`, `analysis_settings.json`, and `Fig9_grouped_nested.png` to the specified output directory. Per-window predictions and the historical Figure-9-style image are generated locally rather than stored as committed files in this directory. This is not the current manuscript Figure 9. The explicit output path keeps the archived result tables unchanged.

The recorded run's software versions are listed in [`analysis_settings.json`](analysis_settings.json); `requirements.txt` provides broader installation ranges. Use the recorded versions and the corresponding input-data commit when checking an exact historical result. The current supplied exports have small rounding differences from the earlier analysis inputs, as documented in the [processed-data notes](../../data/processed/README.md).
